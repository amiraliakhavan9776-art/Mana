# پایلوت بررسی جمع صورت هزینه

این برش روی PR شمارهٔ ۲ و commit `28d330cc920fb374e92651b46f8b9af86f194a3a` ساخته شده است. مسیر قبلی «برو جلو» حفظ می‌شود. این قابلیت فقط جمع ردیف‌های هزینه و اختلاف با جمع اعلامی را بررسی می‌کند؛ حسابرسی رسمی، تشخیص اصالت فاکتور، پرداخت، مالیات، مدیریت پیمان یا تصمیم مالی نیست.

## استفادهٔ محلی

همان نصب آزمایشی `DEVELOPMENT-STAGING.md` را در checkout مستقل انجام دهید. هیچ فایل یا state تولیدی جایگزین نمی‌شود.

```sh
export MANA_DEVELOPMENT_WORKSPACE="$(mktemp -d /tmp/mana-staging.XXXXXXXX)"
chmod 700 "$MANA_DEVELOPMENT_WORKSPACE"
node mana-ai/development-ui.cjs
```

نشانی `http://127.0.0.1:8798/expenses` یا پیوند «بررسی صورت هزینه با درخواست فارسی» در صفحه اصلی را باز کنید. برای آزمون بدون اطلاعات واقعی «نمونهٔ ساختگی» را بزنید، سپس «بررسی صورت هزینه». جمع ۱۵۰۰۰ ریال، جمع اعلامی ۱۴۰۰۰ و اختلاف ۱۰۰۰ باید دیده شوند. جمع اعلامی را به ۱۵۰۰۰ تغییر دهید و دوباره بررسی کنید؛ نتیجه برابر خواهد شد.

- دستور نمونه: «جمع هزینه‌های این صورت را بررسی کن». تشخیص درخواست محدود و قاعده‌محور است، نه درک عمومی زبان یا اجرای هر فرمان.
- واحد تمام مبالغ را صریحاً ریال یا تومان انتخاب کنید؛ هیچ تبدیل ضمنی انجام نمی‌شود.
- CSV UTF-8 یا متن کپی‌شده، با دو ستون `شرح,مبلغ` یا `description,amount`، حداکثر ۱۰۰۰۰۰ بایت و ۵۰۰ ردیف. نقل‌قول، ویرگول داخل نقل‌قول و شرح چندخطی پشتیبانی می‌شود.
- مبلغ صحیح نامنفی تا ۲۴ رقم، با ارقام فارسی/عربی/لاتین؛ بدون ممیز، جداکننده، واحد یا نماد علمی. محاسبه با ماژول بومی `financial/exact-decimal.cjs` انجام می‌شود، نه Number یا مدل.
- فقط اقلام هزینه را وارد کنید. جمع کل باید در کادر مستقل باشد، نه ردیف جدول. عنوان‌های رایج جمع رد می‌شوند؛ عناوین دلخواه الزاماً قابل تشخیص نیستند.
- شماره سطر فیزیکی/بازه سطر، شرح و مبلغ هر قلم نمایش داده می‌شوند. ردیف‌های مشابه علامت می‌خورند اما خودکار حذف نمی‌شوند.
- گزارش شامل برنامه، جمع دقیق، اختلاف علامت‌دار (محاسبه‌شده منهای اعلامی)، هش منبع و محدودیت‌هاست. دریافت JSON اختیاری است.
- داده در حافظه درخواست پردازش می‌شود؛ فایل، تاریخچه یا رسید مالی روی سرور ذخیره نمی‌شود. گزارش فقط با دکمه دریافت در دستگاه کاربر ذخیره می‌شود. صفحه دارای `no-store` است؛ پاک‌کردن فرم حذف امن از حافظه/دستگاه را تضمین نمی‌کند.
- تغییر ورودی گزارش قبلی را نامعتبر می‌کند. درخواست قدیمی پس از تغییر/پاک‌کردن نمی‌تواند گزارش جدید را جایگزین کند.
- هیچ مدل، GPU، shell، سرویس بیرونی یا عملیات پرداخت فراخوانی نمی‌شود. loopback، Host/Origin/token و سقف بدنه حفظ شده‌اند. پورت عمومی نشود.

## آزمون

```sh
node --test mana-ai/tests/expense-pilot.test.cjs mana-ai/tests/development-loop.test.cjs
# با وابستگی‌های Playwright و Chromium نصب‌شده:
node mana-ai/tools/expense-browser-check.cjs
```

بررسی مرورگر جدید، رابط واقعی → HTTP واقعی → محاسبه بومی واقعی را در دسکتاپ/موبایل می‌سنجد؛ نتیجه هزینه تزریق یا شبیه‌سازی نمی‌شود. runner مأموریت‌های قدیمی در این آزمون استفاده نمی‌شود. CI آن را جدا از آزمون قدیمی رابط اجرا می‌کند. در محیط ساخت محلی، Chromium به علت ممنوعیت ایجاد socket شروع نشد؛ تا اجرای موفق مرورگر ادعای قبولی مرورگر نکنید.

شواهد محلی این بازبینی: مجموعه کامل CPU شامل ۴۸۳ آزمون، همگی موفق بدون skip؛ ۲۰ آزمون متمرکز (۱۱ جدید و ۹ مسیر قدیمی) موفق. `git diff --check` و کنترل نحو JavaScript درون صفحه موفق. CI این شاخه هنوز اجرا نشده چون انتشار انجام نشده است.

بازبینی مستقل: ابهام تعداد ستون سربرگ، خواندن ناهمگام فایل و escape نمونه اصلاح شد. آزمون CPU متن واقعی اسکریپت صفحه را اجرا می‌کند و نمونه، توقف منبع در حال خواندن/نامعتبر، جلوگیری از گزارش و دریافت قدیمی و ترتیب پاسخ فایل‌ها را می‌سنجد. این بررسی جایگزین مرورگر واقعی نیست.
