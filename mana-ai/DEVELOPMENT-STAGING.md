# اجرای آزمایشی «برو جلو»

این تحویل یک برش محدود از برنامه جامع MANA AI و Jarvis است، نه تکمیل محصول یا خودتکاملی عمومی. سند اصلی ۱۲ صفحه‌ای `MANA_AI_Jarvis_Master_Plan_FA_v1_1.pdf` (۲۶ اکتبر ۲۰۲۶) کامل خوانده شد؛ بخش‌های ۳٫۱ تا ۳٫۵، ۹، ۱۱، ۱۲ و ۱۷ مبنای این برش هستند. اسناد ثبت قابلیت ۱٫۱ و فهرست تکمیلی ۱٫۲ نیز بررسی شدند. AEC، Company OS، Jarvis خصوصی، شورا و استودیوها از دامنه کل پروژه حذف نشده‌اند.

## کد استفاده‌شده و مرز این نسخه

- رابط از `mana-preview.cjs` واقعیِ ۱۸ نوامبر اقتباس شده؛ ظاهر فارسی، دکمه، دلیل انتخاب و سابقه حفظ شده‌اند.
- دو شناسه واقعی صف ۸۴ مأموریتی و **همان چهار آزمون نام‌برده** بازیابی شده‌اند، نه چهار آزمون ساختگی جایگزین.
- `mission-runtime.cjs` پس از ثبت تفاوت با snapshot تاریخی وارد شده است. قرارداد خروجی نوع‌دار، fingerprint، timeout اختصاصی، preview و تطبیق نتیجه حفظ شده‌اند.
- فایل واقعی `typed-contracts.cjs` از خروجی تازهٔ کاربر دریافت شد؛ فقط محافظ عمق بازگشت، به‌صورت diff صریح، به آن افزوده شده است.
- صف اصلی فقط خوانده می‌شود؛ `sourceStatus` تاریخی تأیید امروز نیست. رسیدها به نسخه کد، آزمون، صف، Node و ابزار ایزوله متصل‌اند. مدل و GPU استفاده نمی‌شوند.
- فقط دو benchmark متصل‌اند؛ موفقیت آن‌ها وضعیت ۸۴ قابلیت را «تکمیل‌شده» نمی‌کند.
- در خطا، نتیجه نامعلوم، قفل رهاشده، تغییر منبع یا خرابی رسید، توقف و بازبینی انجام می‌شود؛ تکرار خودکار وجود ندارد.

## نصب آزمایشی بدون جایگزینی سرور

پیش‌نیاز: Linux، Node.js 24، bubblewrap و پشتیبانی مجاز namespace. نسخه در یک checkout تازه و مسیر داده مستقل اجرا شود. هیچ دستور زیر نباید در پوشه فعال تولیدی اجرا شود. برای رفع خطای sandbox، AppArmor یا تنظیمات امنیتی سیستم را غیرفعال نکنید.

```sh
git clone --branch feature/dot-persian-mission-loop --single-branch \
  https://github.com/amiraliakhavan9776-art/Mana.git Mana-staging
cd Mana-staging
node --test mana-ai/tests/typed-contracts.test.cjs \
  mana-ai/tests/typed-dependency-contract-v03.test.cjs \
  mana-ai/tests/typed-dependency-acceptance-v01.test.cjs \
  mana-ai/tests/mission-runtime.test.cjs mana-ai/tests/development-loop.test.cjs
# پذیرش واقعی: شکست sandbox باید شکست آزمون محسوب شود، نه skip یا fallback.
node mana-ai/development-acceptance.cjs
# مسیر تازه و خصوصی، نه state موجود روی سرور:
export MANA_DEVELOPMENT_WORKSPACE="$(mktemp -d /tmp/mana-staging.XXXXXXXX)"
chmod 700 "$MANA_DEVELOPMENT_WORKSPACE"
node mana-ai/development-ui.cjs
```

روی همان رایانه `http://127.0.0.1:8798` را باز کنید. با «برو جلو» عنوان مأموریت، دلیل انتخاب و نتیجه همان‌جا دیده می‌شود؛ فشار بعدی مأموریت دوم را می‌آزماید. پس از توقف و اجرای مجدد با **همان** `MANA_DEVELOPMENT_WORKSPACE`، رسیدها استفاده می‌شوند و آزمون موفق بدون تغییر نسخه تکرار نمی‌شود. برای دسترسی شخصی از راه دور فقط از تونل امن موجود استفاده کنید؛ پورت را عمومی نکنید. این پایلوت جایگزین احراز هویت چندکاربره، HTTPS و گیت تولید نیست.

## شواهد و بازگشت

`docs/development-provenance/README.md` و patch همراه، تفاوت‌ها و منشأ را ثبت می‌کنند. snapshot تاریخی با سرور فعلی یکی فرض نشده است. پیش از جایگزینی هر فایل مشترک، snapshot تازه و diff واقعی لازم است. تغییر server، ادغام، انتشار، مهاجرت state و راه‌اندازی GPU انجام نشده است.

رسیدها و فایل `.pending` و `run.lock` را برای دورزدن توقف حذف نکنید. ابتدا توقف همه پردازش‌ها و نتیجه اجرا بررسی شود؛ شواهد نگه داشته شود و تصمیم بازیابی ثبت شود. برای آزمایش تازه پس از بازبینی می‌توان یک workspace جدید ساخت؛ این کار قبولیِ اجرای قبلی را ثابت نمی‌کند.

بازگشت این پایلوت: فرایند روی ۸۷۹۸ را متوقف کنید. checkout و workspace جدا باقی می‌مانند؛ هیچ خدمت فعال یا state تولیدی دست‌کاری نشده است.

## وضعیت پذیرش

آزمون‌های CPU و HTTP با اجرای تزریق‌شده تنها منطق یکپارچه‌سازی را می‌سنجند. اجرای `development-acceptance.cjs` عمداً sandbox واقعی می‌خواهد و هیچ جایگزین بدون ایزوله ندارد. در محیط ساخت اولیه، bubblewrap با `Failed to create NETLINK_ROUTE socket: Operation not permitted` متوقف شد؛ بنابراین پذیرش واقعی رابط تا sandbox هنوز **قبول نشده** است. CI جدا برای همین گیت اضافه شده؛ نتیجه CI برای commit نهایی باید جدا بررسی شود. بازبینی سرور فعلی و آزمون کلیک مرورگر نیز مستقل‌اند.

به‌روزرسانی CI: روی commit `1cc1465` مسیر واقعی HTTP → sandbox → چهار آزمون هسته و بازیابی رسید قبول شد. آزمون کلیک مرورگر دسکتاپ/موبایل نیز جداگانه با runner تزریق‌شده قبول شد؛ این دو را آزمون یکپارچه کلیک تا sandbox واقعی یا پذیرش سرور فعلی نمی‌نامیم.

مقایسهٔ خروجی تازهٔ سرور (۱۸ نوامبر): runtime و دو فایل آزمون با PR بایت‌به‌بایت یکسان‌اند. manifest و تفاوت عمدی validator در `docs/development-provenance/` ثبت شده‌اند. دریافت فایل از کاربر، تأیید وضعیت سرویس در حال اجرا نیست.
