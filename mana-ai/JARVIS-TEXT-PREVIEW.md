# جارویس: پیش‌نمایش متنی و فایل قابل ویرایش

نمونهٔ محلی مبتنی بر `src/jarvis/service.cjs`، دستور زبان محدود فارسی و همان Mission Runtime مانا. این ورودی جدید است؛ رابط توسعه و سرور عملیاتی را تغییر نمی‌دهد.

## اجرا در محیط آزمایشی CPU

نیازمند Node 24، Python 3 و وابستگی‌های موجود ابزارهای معماری (`ezdxf`, `reportlab`, `PyMuPDF`). هیچ نصب خودکار یا دانلودی انجام نمی‌شود. در محیطی با این وابستگی‌ها:

```sh
# از ریشهٔ مخزن؛ پوشهٔ خصوصی و اختصاصی بیرون مخزن
export MANA_JARVIS_PREVIEW_WORKSPACE="$(mktemp -d /tmp/mana-jarvis-preview.XXXXXX)"
node mana-ai/jarvis-preview.cjs
```

مرورگر همان کامپیوتر: `http://127.0.0.1:8797`.
این نشانی روی گوشی به سرور دیگری وصل نمی‌شود. پورت را عمومی نکنید. برای راه‌اندازی بعدی همان مسیر را نگه دارید. متغیر `PORT` فقط شمارهٔ پورت loopback را تغییر می‌دهد.

۱. درخواست پیش‌فرض فارسی را بخوانید یا ابعاد مجاز را وارد کرده و «تبدیل ابعاد به درخواست» بزنید.
۲. «نمایش برنامه»: ابعاد برداشت‌شده و سه مرحله را بررسی کنید؛ هنوز فایلی ساخته نشده است.
۳. «اجرای برنامهٔ نمایش‌داده‌شده»: دو DXF، مدل JSON، متره JSON و دفترچه PDF واقعاً ساخته و بررسی می‌شوند.
۴. فایل‌ها از همان صفحه قابل دریافت هستند. فایل DXF قابل ویرایش است؛ داخل این رابط ویرایش CAD وجود ندارد.
۵. بعد از اتمام، ابعاد را عوض کنید و «نسخهٔ جدید مأموریت انتخاب‌شده» را انتخاب کنید. فایل‌های قبلی محفوظ می‌مانند.

## محدوده و شفافیت

- عرض ۸ تا ۳۰ متر، طول ۱۰ تا ۴۰ متر، ارتفاع ۲٫۴ تا ۴٫۵ متر؛ پیش‌فرض ارتفاع ۲٫۸.
- نمونهٔ ثابت دوخوابه/هفت‌ناحیه‌ای، نه طراحی آزاد اتاق‌ها، کنترل مقررات یا نقشهٔ اجرایی. ابعاد ورودی اعلام کاربر است، نه برداشت واقعی زمین.
- PDF تولیدکنندهٔ موجود انگلیسی است؛ رابط فارسی است. صوت، حافظهٔ ترجیحات، عامل عمومی، ارسال فایل بیرونی، پرداخت و انتشار پیاده‌سازی/فعال نشده‌اند.
- ابزار Python ثابت و مورداعتماد اجرا می‌شود؛ ورودی تبدیل به کد یا دستور shell نمی‌شود. این مسیر ادعای سندباکس سیستم‌عاملی ندارد.
- علاوه بر بررسی‌های ابزار موجود، خروجی نهایی دقیقاً پنج فایل لازم و دو پلان تأییدشده توسط `verify_artifacts.py` می‌خواهد؛ هر دانلود دوباره با اندازه و SHA-256 ثبت‌شده مقایسه می‌شود.
- وضعیت مأموریت رمزگذاری‌شده و کلیدها در پوشهٔ خصوصی همان دستگاه‌اند؛ این جایگزین رمزگذاری دیسک یا مدیریت کلید تولید نیست. فایل‌های خروجی رمزگذاری نشده‌اند. فقط دادهٔ آزمایشی استفاده کنید.
- یک پردازش فعال در هر پوشه مجاز است. توقف عادی Ctrl-C قفل را برمی‌دارد. بعد از crash، قفل خودکار پاک نمی‌شود؛ پیش از برداشتن دستی `preview.lock` توقف پردازش قبلی و وضعیت فایل‌ها را بررسی کنید. مأموریت نامعلوم خودکار تکرار نمی‌شود. قطع برق هنگام ثبت فهرست ممکن است `missions.json.new` یا مأموریت ثبت‌شده ولی بدون شناسه در فهرست باقی بگذارد؛ این موارد نیازمند بازیابی دستی و حفظ شواهدند، نه حذف خودکار یا ادعای بازیابی کامل پس از crash.
- سقف ۱۰۰ مأموریت در هر پوشه، درخواست ۸KB و متن ۸۰۰ کاراکتر؛ حذف سابقه خودکار نیست.

## آزمون ثبت‌شده

```sh
node --test mana-ai/tests/jarvis-preview.test.cjs
```

۵ آزمون موفق، بدون skip: تفسیر محدود و منع درخواست نامجاز؛ پوشهٔ خصوصی/قفل؛ ساخت واقعی پنج فایل، تأیید دو پلان، restart و نسخهٔ جدید با حفظ خروجی قدیمی و رد فایل دستکاری‌شده؛ HTTP واقعی با حفاظت Host/Origin/token و محدودیت ورودی.

آزمون پنجم مسیر mount شدهٔ `/jarvis` و عدم پذیرش POST بدون Origin را پوشش می‌دهد.

این شاهد CPU و HTTP است، نه آزمون بصری مرورگر یا پذیرش سرور زنده. انتشار، نصب روی سرور و ادغام انجام نشده است.

## ترکیب با سرور آزمایشی موجود

```js
const {createSession}=require('./src/jarvis-preview/session.cjs');
const {createHandler}=require('./jarvis-preview.cjs');
const session=createSession({workspace:process.env.MANA_JARVIS_PREVIEW_WORKSPACE});
const jarvis=createHandler(session,{basePath:'/jarvis',getPort:()=>server.address().port});
// در callback سرور، قبل از مسیرهای دیگر:
// if (await jarvis(req,res) !== false) return;
// در پایان واقعی کار سرور: session.close()
```

getPort باید از سرور واقعاً درحال listen گرفته شود، نه Host یا forwarded headers. Handler مستقل فقط prefix خود را پردازش می‌کند؛ توکن جدا و Origin دقیق برای POST لازم است. وضعیت completed تنها وقتی در رابط نمایش داده می‌شود که رسید بررسی نهایی پنج فایل/دو پلان هم ثبت شده باشد؛ وگرنه preview_unverified است.
