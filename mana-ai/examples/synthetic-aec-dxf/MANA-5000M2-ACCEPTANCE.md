# MANA whole-project acceptance scorecard

**Decision: NO-GO for a real project.** This scorecard is a test plan, not an engineering report or a declaration of feature readiness. Scope: one fictional, roughly 5,000 m² building, with a whole-building register and a detailed representative floor. All inputs, rates, approvals, schedules, evidence and identities are synthetic. Test privately on an isolated CPU environment. No project/client data, external sharing, production deployment, real commitments, payments, or construction use. Engineering/legal/financial acceptance is outside this exercise and is never implied by a pass.

Reference: MANA & Jarvis development specification v1.1, sections below. IDs and pass rules are stable. Record one result per gate: `PASS` (complete gate evidence and independent review), `PARTIAL` (named measured subset only), `FAIL`, `NOT_PROVEN`, or `N/A` (specific reason and reviewer; cannot be used for an applicable gate). Required checkpoints: freeze scope and fixture before execution, publish no data, and keep owner and professional review separate from measured test outcomes.

## Cross-capability failure-sensitive test (G15-REVISION)

1. Freeze the brief, model and one building-level window ID. Pin baseline quantities, mock rate/version, affected procurement item, schedule activity, contract change draft and booklet references. Store checksums and test assumptions before change.
2. Make one controlled dimensional revision to that window. Preserve its stable ID. Independently reopen BIM and CAD, verify before/after geometry, and calculate the expected window/façade or finish delta and value from the fixture. No software/model prediction is accepted as the independent oracle.
3. Trace the observed delta through the model, drawing, takeoff/estimate, procurement, schedule, technical-office record and both booklet exports. Compare with the independent oracle. Where a dependency needs professional input, explicitly surface it, do not invent a change. Fail if an affected artefact silently stays current, if an unaffected model/object/report changes, or if a revised input reuses a prior version's approval.
4. Recreate the verification from the same checkpoint after restart. Verify duplicate events don't re-apply effects, unauthorized review fails, the recorded source trail is reproducible, and no external effect occurred. Then restore the baseline in a separate copy and compare hashes and source bindings.

## Release decision

Attach per-gate indexed evidence: fixture/revision and artifact digests, exact command and environment, measured metric/status and expected result, failure/exception log, and independent reviewer record. A real project remains blocked unless **every applicable gate** is PASS, each N/A is explicitly justified and reviewed, no high-severity regressions remain, and the owner separately decides whether to proceed. Passing here cannot replace later professional sign-off, project-specific input validation, security/deployment approval, or user consent. General marketplace, arbitrary industry expansion, HR/payroll, personal wealth, live publication and base-model training cannot be credited as proven by this project.
