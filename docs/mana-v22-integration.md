# Selective integration of the V22 source archive

Source archive SHA-256:
`985f71cb89e39df961fe2eed0ae73b04c1c7bc66387b4ab7daae74b1cd42690a`.
The original archive is preserved unchanged in the consolidated release under
`reference/`. It is reference material, never automatically unpacked or executed.

Sixteen compatible native modules were imported: schematic/layout/access/quality/
revision calculations, shared Jarvis planning and AEC/quality bridges, limited
skill compilation/repair, static patch screening, optional signed test receipts,
restricted patch review, requirement tracking, explicit project ledger review
and a bounded coding-cycle coordinator. Compatible tests, examples and local
commands accompany them. Exact paths are recorded in `v22-import-provenance.json`.

The current mission runtime, principal Jarvis service, approval store and hardened
Python sandbox remain authoritative. The source archive's older copies were not
substituted. Hierarchical planning, execution work budgets, scoped adapter calls,
replanning/recovery, current finance/quantity/change-impact services and existing
training checkpoints are preserved.

Imported quality checks now reject equal-area substitutions with different room
dimensions, while allowing the solver's explicit 90-degree orientation freedom.
They also retain original-brief adjacency requirements rather than trusting
weakened layout claims. AEC bridge factories bind their tools to the runtime's
project scope and to hashes of the solver/reviewer/helper source dependencies.

Seven original modules remain inactive in reference material: both alternative
Python verifiers, sandbox-readiness, native repair sandbox, native skill/repair
mission adapters, and the generic module-patch mission bridge. Their arbitrary
Python-test protocol is not automatically substituted for the current sandbox's
parent-verified JSON benchmark protocol. The unshare backend is not activated.
Missing integration is not replaced with host execution or success claims.

The original FILES.sha256 mismatches for module-patch-review, Python verifier and
its test are recorded as provenance issues. The consolidated release creates a
fresh manifest covering the actual integrated bytes and unchanged reference ZIP;
this does not certify the archive's original authorship or historical manifests.

Important boundaries: compiled skills are a small expression DSL, not a trained
general coder. Its Python Decimal context has finite precision and is not used
as the authoritative company financial calculator. Mutation search and injected
verifiers in tests do not establish model intelligence or real sandbox acceptance.
HMAC receipts require an independent trusted runner and protected key. Static risk
screening is not a security proof. Geometry remains schematic, without structural,
permit, fire, accessibility or full construction-document acceptance.

All imported local commands run only when explicitly invoked. No service starts,
model weights change, source patch is applied, financial entry is posted or live
deployment occurs during installation. Production authority and independent
professional review remain required.
